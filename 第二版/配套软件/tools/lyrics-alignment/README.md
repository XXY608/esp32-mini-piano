# 人声辅助逐字对齐

这些是第一方辅助脚本的唯一正式源码。Build-Release.ps1 将 `.py` / `.json` 同步到工作区 `work/lyrics-alignment`；venv、模型、缓存、录音和每次任务输出只放在该运行目录。

界面入口：直接点击“一键配词并导入”，选择原始 CCMZ；已导入 CCMZ 时处理当前曲目。自动搜索 LRCLIB 的歌词版本，使用有链接记录的完整人声，分离人声、提取字音时间，再以旋律匹配定位到源谱音符，直接保存 TXT 和同名逐字绑定。已核对的来源登记在 known-sources.json；其他歌曲通过公开视频搜索查找时长相符的人声候选，无法获取或处理失败时保留原曲谱。

结果自动保存，不再强制打开手动校准窗口。“校准歌词”保留为可选工具。每个字／音节保存明确的起止音符，一字可跨多个音。音高支持不足、发音跳过或起点偏离会标记“待核对”；自动保存不等于准确率验收。全文逐音节检查会拒绝漏字、多字和没有位置的结果。拆分仅复制相同音高，按播放器四分之一拍单位分配，保留原有量化后总时值。源 CCMZ 不修改。

版本 2 的对应方式：先按真实发音停顿分出子句，再在完整音符与四分之一拍边界之间动态分配音节；优先保留原音符边界，必要时拆分。音高代价按每个源音符累计，避免长拖腔掩盖错误的起始音。模型识别用“哦”处理中文演唱中的 Oh，显示仍保留原字；输出逐字核对原歌词，不再只检查 TextGrid 文件数。诊断只比较韵母发声部分，避免辅音起始段借用前一个字的音高。相邻歌词段的重叠不再让前一句抢占后一句的音符。临时 CCMZ 在每个覆盖音符写显式范围标记，C# 合并为一个字的准确结束索引，不把间奏延长到上一个字中。

如果相邻片段的逐字时间相互重叠，refine_overlaps.py 会把涉及的歌词与人声合并作一次上下文重对齐，结果留在 context-aligned 和 refined-tokens.json；不按平均时长硬切重叠区。真实样本第 31/32 段的跨句重叠已由这一流程消除。

版本 6 会在联合推断后再次检查边界；若改动触及第三句，自动扩展已有上下文组继续推断，直到没有重叠。上下文组只能扩大，已完整推断的同一组仍重叠时拒绝结果，避免重复重算或硬切时间；各轮证据留在 context-aligned/round-*。

版本 7 在分配曲谱音符前，将没有实际换气间隔（不超过原有 200 ms）的相邻 LRC 显示行一起配对，保留各字原来的显示行与发音时间。LRC 换行本身不再让上一句尾字抢走下一句弱起音；有实际换气的边界仍分开。《老男孩》第二次“江河／一去不回”和“了吗／事到如今”共 8 字的范围由此修正，原 35 项中“去／到”的音高诊断和“如”的起点诊断消除，剩余 32 项音高证据不足或冲突继续保留。音高、总拍数和诊断阈值不变；第一首 338 字的全部音符范围及 21 项参考谱佐证保持不变。一键自动导入、保存和原件重导入恢复沿用现有流程。

版本 8 增加 `position_evidence.py`：先使用原阈值，以Praat与pYIN两路持续目标音确定可靠锚点，再取疑点前后各两个锚点拟合局部谱时／发音时关系。目标字自身的音高不参与这项证明，也不将新推断的字再次作为锚点。要求局部残差和目标音头误差不超过120 ms；竞争音符在40 ms帧加实际残差的不确定区间下仍不能成立，且字音终点不能超出该音范围，才接受位置支持。共享音符、跨多个音、缺单侧锚点、局部节奏不稳定及候选有歧义时保留诊断。该模型用于验证既有逐字位置，不据它拉伸时间、平均分词或改音高。

版本8当时《老男孩》32项中13项获得上述局部位置支持，另19项继续保留；当前版本9结果见下段。原32项音高／发声诊断全部保存在pitch-review及正式绑定中，不能把位置支持叫作音高完全一致或独立带词谱核实。每字的锚点、拟合参数、候选误差及原诊断写入position-review.json，随C# BoundLyric.PositionEvidence保存和重载。可选校准窗口可查看依据；改字、改范围或参考时间后旧依据失效。一键导入仍直接保存，不要求用户逐字手调。

版本9增加六锚点辅音时序模型：用相邻字的辅音时长学习节拍落在辅音起点到韵母起点之间的位置，系数限制在这个物理区间，不使用目标字的发音时间或音高训练模型。六个锚点中的四个内部字依次留出预测；最大误差超过原120 ms门槛时拒绝，目标辅音时长超出已有样本范围40 ms以上也拒绝。竞争源音符仍须在实测不确定区间下唯一，且新旧模型给出不同可靠位置时保留疑点，不能挑选迎合当前绑定的模型。四锚点旧依据继续兼容，六锚点新依据及所有锚点编辑后的失效处理随绑定保存。

《老男孩》新增“现”（token239）的位置支持，累计14项、剩18项，原32项声学诊断保留，谱面和逐字范围未改。一字多音仍需完整音高／范围证据，不能靠该音头模型通过。评估入口 `tests/evaluate_positions.py JOB... --output REPORT.json`：逐一留出可靠字，对比原模型与新模型的时间预测误差、记录错误位置提议，同时报告全部可比字和通过内部验证的子集；它不是人工逐字准确率。实验中的复杂变速曲线误差更大，没有用于正式流程。

版本10修正独立音高复核的一字多音误判：原来按音级集合检查，会把倒序、缺少回落或半音中点同时落入两个容差范围的轨迹判为支持。现在依源谱音级顺序逐段寻找两路估计器均支持、持续至少原80 ms的连续证据；相异音级必须各自是唯一最近目标，返回原音级必须在后续真正出现。相邻同音级保留既有连音／八度处理，不凭此声称已验证所有八度跳进。逆序等反例改为out-of-order-targets，原65%／0.75半音门槛不变，单音滑音复核和字音范围保持。此项作用于进入独立音高复核的字，尚不是所有未标记多音字的人工验收。两首缓存音频阶段回放结果保持第一首0项、老男孩18项归属待核对；没有为了展示收益清标。

版本11把这项独立复核覆盖到所有包含不同音级的多音字。原来的总音高支持比例即使为100%，也可能只唱了其中一个音，不能跳过顺序检查。新增melisma-order-unverified进入Praat／pYIN复核，仍不足时再用pYIN／CREPE；只有完整顺序通过才撤销此原因，不影响其他诊断。相邻同音级及八度重复仍沿用原处理。两首实际音频回放发现此前未标记的多音字疑点：第一首167“临”、336“叹”两项；老男孩新增67、83、118、173、214、230、294、308、320、322共10项。当前分别2项、28项待核对，第一首21项参考谱佐证和第二首14项位置支持仍保留。新增疑点表示缺少逐音持续或返回证据，不直接判定这些字配错，也不改音符或逐字范围；不能把以前0／18项当成全面检查已经通过。

版本12找到第一首两项的实际来源问题：CCMZ将明确标注arpeggiate的和弦按MIDI先后奏响，下方伴奏音比主旋律提前40 ticks；仅按相同tick取最高音会误把这些下音当成旋律。score_melody.py按原谱分组、音高及明确琶音标记识别下方和弦音，C#原件导入采用相同规则；没有明确标记或音高资料不全时保持原逻辑，不按时间接近程度删除音符。第一首仅过滤n_58_8、n_58_10、n_110_0三条伴奏事件，“临”恢复D#–E–F#的旋律，“叹”保留C#主音；原源CCMZ不改。第一首338字的声学时间全部不变，只有167／336的源音符集合去掉伴奏，其他336字的源事件集合不变，待核对回到0、原21参考谱和原21声学诊断保留。老男孩没有适用的明确琶音下音，全部位置／范围／时间和28疑点保持。版本11的23项原始声学记录和旧正式绑定仍保留在其任务及历史归档，不能把修正源提取称为降低音高阈值。

版本13修正word_alignment.py中的音高取样：原来删除无声帧再插值，会跨过静音制造滑音，并把首尾有效音高延伸到字头／字尾的无声区。现在保留无声帧为缺失值，禁止首尾外推，缺失处沿用原0.5无证据代价；完全无有效音高时保持原处理。字头无声和内部缺口两个构造反例中，旧版把第二字的弱起音分给第一字，新版按已有时序恢复正确边界。连续发声、全无声及两首真实样本回归保持；800字全部范围／时间及证据决定没有变化，老男孩28项继续保留。这项修复不代表测得真实歌曲人工准确率提升。原65%／0.75半音／80 ms诊断门槛保持，一键保存与同源恢复不增加步骤。

版本14让位置竞争遵守播放器已有的最小四分之一拍容量：仅当当前时序模型的冻结可靠锚点已经占用某个单格音符的完整0–1区间，才排除该音符作为另一字的竞争位置。多格长音、未冻结的字、部分区间和自由竞争者仍保留；不把所有已分配音符都排除。占用者包含在原四／六个anchorIndices内，occupiedSingleUnitNotes保存对应关系，编辑占用者会沿用现有依赖失效逻辑。模型、120 ms误差／候选间距及原音高门槛不改。《老男孩》42注／209人／211你新增局部位置支持，累计17项、25待核对，原42项声学诊断保留；第一首0待核对保持，两首全部源音符、字音范围和发音时间未改。215在的竞争音符属于尚不可靠的214今，不能据占用排除。此项支持依赖既有可靠锚点与可播放约束，不是人工逐字准确率。

重复处理时，audio_source.py 只复用任务目录中 URL 相同且原始录音 SHA256 与来源登记一致的文件；重新解码后仍执行完整人声分离和对齐。部分下载、不同来源或校验不符的录音不能作为缓存。第二首的发布后重跑曾遇到 CDN 超时，已用这条自动路径解决，无需用户重下或指定录音。

版本 4 增加独立音高复核：保留原 65% 支持度与 0.75 半音诊断，在被标记的韵母上使用 pYIN（10 ms 帧）与原 Praat 轨迹交叉比较；仍未解释的部分再使用 CREPE-full 神经音高与 pYIN 交叉核实。普通目标音需要持续至少 80 ms，且满足原支持度要求。连续滑音必须落在目标音与相邻谱音之间，保留实际升降方向；字头倚滑音需有连续趋向目标的轨迹、稳定收尾和两路证据。多音字需要每一种目标音高都有持续证据。短暂经过正确音、微弱发声、两种算法冲突或无法解释的旋律差异仍保留标记。复核不修改源谱音高、字音时间或音符归属；逐项原始支持度、方法、结果与残留原因写入 pitch-review.json。

版本 5 加入有来源的逐字带词谱复核。known-sources.json 可登记 score_url；目前支持简谱空间公开页面的显式字音标注。程序自行读取记谱数据，先以整曲旋律寻找唯一的拍点偏移和调性对应，要求至少 90% 音级匹配且最佳位置显著优于其他重复段；再核对具体字、相邻歌词和音符范围。被两个已匹配音符夹住的局部差异，只接受唯一的顺序音高匹配，不能仅按字数分配。同音拆分或证据冲突不能由单个同字标签直接确认。取回失败时使用带校验值的本地来源缓存；没有有效参考时继续音频流程并保留疑点，不要求用户操作。

本机真实样本回归：338 个字／音节（旧版 335，漏 3 个 Oh），3 处同音拆分，主体仍为 411.75 拍。版本 4 的 43 项音频佐证保留；其余 21 项现在获得独立带词谱的位置佐证，字音归属待核对为 0。原唱音高／时间诊断仍有 21 项，记录在 acousticReviewReasons、pitch-review.json 和正式绑定的 AcousticDiagnostics；不会把位置已核实写成音高完全一致。两处参考谱音高与当前 CCMZ 相差 3 半音，原谱音高及字音范围均未更改。参考整曲 352 个音符有 339 个音级匹配，343 个音符完成配准，前奏偏移自动识别为 32 拍。21 项的来源 URL、原始页面 SHA256 和诊断随正式绑定保存、重载；可选校准窗口悬停可查看来源，修改字或位置后旧佐证失效。

单元测试入口 tests/test_alignment.py；设置 PIANO_LYRICS_REAL_JOB 可启用实际样本的覆盖和边界回归，Build-Release.ps1 在本机环境存在时自动运行。此曲的位置佐证不代表任意曲目准确率，也不等于人工逐字听觉或游戏输入验收。

版本 6 修复第二首真实 CCMZ 暴露的选源和裁剪问题：先核对曲名与源谱歌手，再比较时长；拒绝时间轴超过声明时长的歌词。源谱把曲名误填为歌手时，使用已核实来源中的歌手信息；中文／英文艺名只采信登记的别名。LRCLIB 连接瞬断最多重试两次。calibrate_segments.py 以开头四句联合推断，至少两个句首在 0.5 秒内同意同一偏移，才自动补偿录音发行版本的引入时间；原始逐字时间仍由 TIFA 推断，不按句长平均分配。最后一行保留录音尾部供模型判断，不以不可靠的末尾空白 LRC 时间截断末字。

第二首真实样本为轻简-cty 的《老男孩》C 调 CCMZ，源 BPM 80，页面 https://www.gangqinpu.com/cchtml/1054669.htm ；人声为 Dreamer Music 发布的官方 MV https://www.youtube.com/watch?v=vw9g4So5f8k 。测试使用 PIANO_LYRICS_SECOND_REAL_JOB 与 PIANO_LYRICS_SECOND_REAL_SOURCE，验证全文、逐字范围和原件重导入；WPF 从真实处理结果执行一键自动保存，不要求校准窗口。较早测试的 72 BPM 编曲未得到完整顺序对应，被拒绝，不能将它列为已支持。音频诊断保留，不把“462 字都有范围”当作所有范围均已准确验收。

CCMZ 导入时跨小节长音按同音时值分段，逐字范围与谱面签名同步映射到新索引。第二首版本6当时有4处配词同音拆分、634个播放索引；版本7修复跨行弱起后减为2处、632索引，当前版本9保持此结果。跨小节排版增加的32个同音分段、329.5拍、83个小节显示行（末行1.5拍）不变。旧同源正式绑定仍由原件SHA256恢复，不因导入器排版更新而覆盖已有校准。

选中一个字，可试听原唱该字的片段，再试听对应音符。绑定保存原唱本地路径、来源 URL 和逐字时间，重新打开校准窗口仍可比较；删除处理记录后原唱试听不可用，音符绑定与正常播放仍有效。

处理记录：jobs/<任务>/audio/provenance.json（录音页面、发布者、时长、校验值）；candidate-alignment.json（字音时间、源音符、疑点及拆分数）；aligned.ccmz（本程序使用的临时单音带词导入包）；各阶段日志。普通 TXT 不混入歌词，最终绑定仍为同名 .lyrics.json。

本机环境：Python 3.12 独立 venv，CPU PyTorch 2.14.1+cpu、TIFA、Demucs 4.1.0、g2pflow 0.3.1、librosa、Parselmouth、torchcrepe 0.0.24、yt-dlp、imageio-ffmpeg。CREPE-full 权重由官方 torchcrepe 安装包提供，处理时无需下载；置信度使用官方示例的 0.21，低于 -60 dB 的静音不作证据，逐片段固定随机种子避免解码抖动改变诊断。完整依赖可由运行目录 requirements-frozen.txt 核查。首次准备环境需要下载模型；当前工作区已经部署。单独复制 EXE 或发行 ZIP 不包含该模型环境，必须保留本工作区 work/lyrics-alignment；普通导入/播放不依赖它。
