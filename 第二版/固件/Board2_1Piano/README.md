## 0.6.9 修复真实手机分块上传

固定Arduino Core 2.0.17 WebServer的canRaw POST分支不解析URL查询参数。原0.6.8把会话和偏移放查询串，导致首块返回invalid sample chunk or session。0.6.9改用已收集的X-Sample-Session/X-Sample-Offset请求头；保留CRC回读、事务提交及原歌曲。更新固件后刷新手机网页再上传。网页模拟测试覆盖无查询参数的实际多块二进制、旧查询方式拒绝、错误会话和非法偏移；软件通过不代替本板真实上传验收。

## 0.6.8 不拆卡上传音色

SD卡插在屏幕后卡槽内即可，通过Wi-Fi网页分段上传，USB仍为串口。
1. 手机或电脑连接机身热点，在浏览器打开 http://192.168.4.1/ （或已配置局域网地址）。
2. 网页“上传音色到SD卡”选择本机已有的3.hps～10.hps，可多选，然后点“上传音色到SD卡”。电脑里的正式资源位于ESP32项目work-build/Board2_1-sd-card/piano-samples。使用手机时先将对应HPS文件传到手机，或改用电脑连接机身热点打开网页。
3. 页面显示逐文件进度；全部显示“已上传并校验”后，在上方演奏设置选音色并应用。当前正在使用的音色上传成功会自动重载，不必取卡或重启。

## 最高音量（0.5.1）

当前扬声器以 `pcb-enclosure-design/harness-user-spec.json` 的用户确认版本 A 为准：4Ω、额定3W、最大5W；历史“测直阻约5.5Ω而按8Ω使用”的早期判断不再用于此设置。供电沿用 DCP 5V，MAX98357A 的 GAIN/SD 仍保持模块原默认接法。

0.5.1把PCM总峰值从600提高到28672（16位满幅的约87.5%），其余0～100%按原比例调节，0%静音。0.5.2起，纯音在这个总上限内按下节进行音区衰减，不能再认为每个音都同幅度。按芯片GAIN悬空9dB、DAC满幅参考2.1dBV估算，正弦输出约3.14Vrms，4Ω负载约2.47W。芯片数据表5V/4Ω条件约2.5W@1%THD+N，3.2W对应10%失真；软件不将扬声器的5W最大值当作可持续输出目标。纯音、合成音色和节拍器的RMS/响度不同，100%不是所有音色都输出恒定瓦数。

这只是依据典型规格的设置，模块实际增益、供电压降、扬声器阻抗随频率变化以及真实不失真音量尚未实测，不宣称已测得2.47W或最大声压。新版同一百分比会明显更响；上传后先调低音量，再逐步加到100%试听。默认开机音量/已保存百分比逻辑保持原样，没有强制开机满音量。

来源：[ADI MAX98357A/MAX98357B 数据表，第5页功率/增益表及第28页 Gain Selection](https://www.analog.com/media/en/technical-documentation/data-sheets/max98357a-max98357b.pdf)。原生测试使用固件同一峰值，覆盖10/50/100%输出、静音、各音色和节拍叠加的16位样本范围；测试不是功放或扬声器实测。

## 纯音音区均衡（0.5.2）

用户实板反馈：音量10%时，纯音高音特别响，低音相对很小。0.5.1同一渲染器的PC诊断在MIDI48/60/72/84、音量10%下测得PCM RMS分别约2026.91/2026.32/2027.00/2026.93，数字幅度基本一致；这不能证明扬声器实际声压或主观响度相同，也不能把全部差异直接判为某一硬件故障。

本版先针对用户确认的“纯音”加入起始试听曲线：C3（MIDI48，约130.81Hz）及以下增益1；高于C3时，增益=130.81278265/实际频率，即每升一八度幅度减半（约−6.02dB）。低音1/C3、中音1/C4、高音1/C5和C6分别使用1、0.5、0.25和0.125倍的原幅度。按实际发声音高计算，半音和移调也连续变化，手动/播放/跟弹使用同一音频路径。保持正弦波，不通过增加谐波改变“纯音”，不放大低音超过既有上限；起落包络、0%静音保留。

这是依据反馈选择的一版试听参数，**不是扬声器频响测量值，也不是ISO等响度标准曲线**。只能先减小高低音听感差距，不能承诺各音声压已经相等。钢琴/风琴仍保留原音色幅度设计，节拍器点击音也保持原逻辑；它们尚无本轮均衡试听反馈。最高PCM上限28672保留，但高音100%不会回到0.5.1未经补偿的幅度。

0.5.2已由用户烧录并试听，反馈音量“感觉还行”；该主观结论不是全音域声学测量。本版保留相同补偿和已有PC回归测试，只有用户报告新的具体异常时再定点调音。

## 双行谱面规则

- “曲谱与练习 → 显示歌词”：白键1/2移动到该项，3切换，设置保存到NVS；网页“演奏设置”也可开关。开关默认关。始终只有两行简谱，开时每行下方增加歌词，关时音符恢复较大高度与留白；无歌词歌曲不生成或猜测歌词，自由演奏不显示歌词。
- 网页“导入歌曲”中，谱面和逐音歌词分别输入。歌词按空格分项，每个非休止的原始音符占一项，无词或一字多音的后续音用 `_`；休止符及延长横线不占项。例：谱面 `1 — 0 2 3`，歌词 `长 _ 音`。项数不匹配会阻止上传，避免错位。JSON导入、上传及下载保留每音`lyric`，纯TXT不加歌词。
- 长音只有起始数字显示歌词，延音格和跨行延音不重复歌词。歌词按显示谱行合并为整行，当前整行蓝绿高亮、下一行灰色预告，两行居中同列；不再逐字改变颜色。到下一行首个有词音符时，用260ms局部向上滚动接替；整行休止或跨行延音保留上一行歌词直到新行开始，末行歌词保持到结束。音符光标继续逐音跟随，和整行歌词高亮互不冲突。歌词行采用现有谱面分行（每行最多8格／源换行），不是推断原歌句界；超过304像素的文本仍裁切，不修改原歌词数据。

- 每行最多 8 个显示格；导入 TXT 的换行保留为分行点，过长行按宽度拆分，小节线保留且不增加停顿。短行按可用宽度分布。只显示当前行与下一行，末行没有新内容时不重复填充。
- 自动播放按实际节奏推进；跟弹等待正确音高后亮起，错音不推进，重复音仍需松开再按。目标等待/暂停时为蓝绿色外框，发声时为填色并短暂下沉，形成按下反馈。自由演奏页显示七个音阶键，按哪个亮哪个。
- 高/低音用上下点，升号靠左，半拍/四分之一拍用下划线，附点靠右；长音展开为数字和延音横线，光标随拍推进，长音跨行时仍保持发声。JSON 的非标准时值按近似下划线显示，播放使用原始时值。
- `1=C` 表示当前数字音阶的实际音高参考，随移调变化，并不声称原曲一定是 C 大调。没有提供拍号时显示“拍号未标”，不会套用示例的 4/4。网页导入可填写源谱拍号，也可在 JSON 中提供 `timeSignature`。
- 旧歌曲只有音高/时值时，自动每 8 格分行，无法恢复已丢失的小节线与原谱换行；重新从 TXT 上传可保留这些信息。原 HTTP 歌曲格式继续兼容。
- 显示使用与固件相同的本机渲染测试，分行和高亮变化只重绘相关区域；不改变独立音频/按键任务。软件预览不能证明 SPI 实物刷新速度。

## 机身操作

正常演奏：七白键加LOW/SHARP/HIGH修饰。HIGH单独按住1.2秒进入菜单，菜单内按一下HIGH直接退出；只要本次按住曾与其他键组合，就取消菜单候选，仍作为升八度修饰。进出菜单及启动播放后等按键全部松开，防止误发音。

首页为两列三行六卡片；1/2按行顺序遍历，边界停留。保留上次首页焦点，不保留未确认参数。菜单中琴键只导航不演奏；自动播放在打开菜单后继续，按“暂停”才暂停。

| 分区 | 内容 |
|---|---|
| 选择歌曲 | 直接打开曲库，选定后进入演奏模式 |
| 演奏模式 | 选定模式后，可开始演奏或播放音乐，也可切换播放模式和歌词显示 |
| 音色与音量 | 纯音/钢琴/风琴三个可见选项，音量0～100% |
| 节奏与调性 | BPM20～400、节拍器、移调−12～+12 |
| 手机连接 | 实际热点名/密码、热点启动结果、Wi-Fi连接设备数、HTTP地址和操作步骤 |
| 设备状态 | 固件版本、SD/内部存储状态、音频/按键任务状态、十键检查 |

| 按键 | 菜单用途 |
|---|---|
| 白键1/2 | 上一个/下一个；音量编辑例外为1增加/2减少；连接页前后滚动 |
| 白键3 | 确认、打开编辑、完成编辑；选曲列表中选定 |
| 白键4 | 返回；编辑中取消并恢复进入编辑时的该参数；选曲中取消候选 |
| 白键5/6 | 非编辑时音量−5%/+5%；BPM编辑中−10/+10；其他编辑页无动作 |
| 白键7、三修饰键短按 | 菜单中无隐藏功能 |
| HIGH单独按一下 | 退出菜单；未确认参数按取消处理 |

音量编辑步进 1%，长按 1 或 2 连续调整。BPM 普通编辑和移调步进 1。实时调整不额外触发试听音。3 完成后保存，保存失败会提示。4 或最右键退出会恢复当前编辑字段。手机修改同一字段时结束机身编辑，并采用手机设置。

选曲列表显示实际中文曲名、序号／总数、源谱 BPM 或默认播放 BPM。四首同屏，选中曲的长名在下方两行自动分页。确认曲目和演奏模式后，按「开始演奏」从头开始所选模式，或按「播放音乐」自动播放。同一首歌以同一播放模式运行时，可暂停或继续。内置音阶始终保留，最多 512 首，网页列表超过 64 KiB 时提示。

连接页1/2翻页；使用Wi-Fi/HTTP，不初始化BLE，不把热点关联设备数写成“App已连接”。设备状态的逐键检查显示10键亮灯，琴键不发声，4返回；HIGH按一下仍可退出。任务初始化状态不是硬件验收结果。

彩屏菜单在现有Adafruit绘图库上实现，深蓝灰底、薄荷焦点、分区彩色图标/卡片和参数窗口。不引入上游WouoUI源码、OLED驱动或编码器依赖；保留此前借鉴的焦点/弹窗思路。MenuModel.h负责交互，MenuScreen.h供TFT和PC预览共用，静止画面不重绘；SPI流畅度待实板确认。

## 手机连接和导入

1. 设备正常供电，手机连接 `HarmonicaPlayer-ESP32`，密码 `harmonica`。手机若提示无互联网，选择保持连接。
2. 浏览器打开 `http://192.168.4.1/`。在“按键检查”逐个测试所有键，再播放内置音阶。
3. TXT 可以直接选择根工作区“简谱”目录里的正式曲谱。文件名包含 `源谱 BPM：XX` 时自动读取；没有标注则显示 120 为默认播放速度，用户应填写合适速度，不冒充源谱 BPM。
4. 源谱有拍号时可在“拍号（可选）”填写，例如 4/4；未标注则留空。检查通过后上传，再选播放或跟弹。音色/节拍器也可从页面操作。App在设备页填写上述地址进行连接测试；网页也可直接使用，无需互联网。

TXT 语法：`1`～`7`、`【1】`、`（1）`、`#1`、`0`；`_` 半拍、`__` 四分之一拍、`.` 附点；独立 `—` 延长前音一拍。括号包住音符与时值，如 `【#4_.】`。小节线和换行用于排版，不增加停顿；非法内容直接报错，不静默丢弃。未提供拍号时只统计总拍数，不声称已验证每小节拍数。

JSON 仍为 App 的 `SongPayload`：id/title/bpm/notes，每音 pitch(0休止或1～7)、octave(−1～1)、sharp(bool)、durationBeats(1/64～64)。可选歌曲字段 `timeSignature`（如 "4/4"），可选音符字段 `barBefore` / `lineBefore`（布尔值）和 `lyric`（单行UTF-8文字，最多24字节，休止符不带词）；旧文件不必补字段。最大 120KiB / 1024 音；未标 BPM 采用 120 播放。上传文件中的额外歌词字段保存于原 JSON，网页下载原文件可保留。

## 本版实板验收顺序

1. 确认版本0.6.2、朝向琴键的双行简谱；低音量逐键试音，确认原音量补偿保持。
2. 测三修饰组合、多白键优先/回退、松键静音；HIGH单独长按进入、按一下退出菜单，组合演奏不能误进。
3. 六入口均可达；3确认/4返回；音色三选项、音量、BPM和移调编辑完成/取消均有效，长按退出取消。测试手机改同一参数时不被旧编辑回滚；保存失败应明确提示。
4. 真实曲名列表选曲但不播放；不同曲播放、同曲暂停/继续、从头跟弹、循环、停止、白键接管。核对换行/小节、休止/重复音、长音跨行和逐音高亮。
5. 连接页热点名/密码/地址实际可用，设备数只代表Wi-Fi关联；手机App/网页能上传与控制。设备状态及十键诊断正确，诊断4返回。
6. 插好FAT32 SD后上电，上传/下载/删除同一曲，重启核持久化和删除不复现；无SD检查闪存回退。闪存格式化仍只在网页明确确认，不格式化SD。
7. 断网机身选曲、长歌曲、网络请求时音频/按键响应和持续运行。确认菜单和网页不再出现录音入口，存储中旧歌曲仍可播放/下载。

SD换卡后需重启。音频延迟、TFT/SD共总线稳定性、Wi-Fi覆盖、最大音量/音色及Flash断电恢复仍需实板验证。0.5.2的音量试听不能替代本版整机验收。

## HTTP 接口

保留：GET `/api/status`、GET `/api/songs`、POST `/api/songs/upload`、POST `/api/song/play`、POST `/api/song/teach`、POST `/api/song/stop`、POST `/api/device/volume`、DELETE `/api/songs/{id}`。

其他：GET `/`、GET `/api/songs/{id}`、POST `/api/song/pause`、POST `/api/song/resume`、POST `/api/device/settings`、POST `/api/storage/initialize`。

settings 接受部分字段：instrument(0～2)、bpm(20～400)、transpose(−12～12)、metronome(bool)、repeat(bool)、showLyrics(bool，默认false)。未知或非法字段整次拒绝。0.6.0移除录音路由和status录音字段，旧App的歌曲/音量接口保留；历史曲谱文件不被自动删除。初始化闪存须精确 JSON `{"confirm":"FORMAT"}`，只允许未挂载时执行。POST JSON 流式接收限 120KiB，不使用 SDK 默认的无上限正文分配。

## 中文界面字库维护

界面文案集中在 DisplayText.h，字体数据位于 ChineseFont.h（ASCII 8×16、中文16×16）；渲染器按UTF-8解码，每个字形通过现有Adafruit TFT驱动批量写入。中文功能提示覆盖主界面、菜单、音区、音色、暂停、网络、存储和音频状态。HIGH 单键长按及rotation=3保持有效。

字库为 GNU Unifont 17.0.03 子集，共 6867 个字形、218224 字节点阵，包含 GB2312 汉字、ASCII、书名号及界面字符。曲目列表中的超长曲名下方分页显示，卡片摘要省略，字库外字符显示问号。逐音歌词使用相同字库，超宽歌词按显示格宽截取。源字体许可证和版权说明保存在 fonts 目录，固件运行无需另外安装字体。若增加字库外界面汉字，运行 Firmware/Generate-ChineseFont.py --font work/ESP32-S3-mini-piano/work-build/font-source/unifont-17.0.03.hex.gz 重新生成。统一构建会检查界面汉字是否都有字形。
